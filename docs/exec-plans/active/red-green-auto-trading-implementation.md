# Red-Green 자동매매 구현 계획

## 목표

Pine Script `Red-Green Signals + SL/TP v9 (Trail Fix)`를 SUPERRICH의 메인 자동매매 전략으로 구현합니다. 우선순위는 신호 재현성, 리스크 통제, MT5 주문 안정성입니다.

## 1단계: 전략 타입과 설정

- 캔들 타입을 정의합니다: time, open, high, low, close, volume.
- 전략 파라미터 타입을 정의합니다.
- 포지션 상태 타입을 정의합니다.
- 주문 의도 타입을 정의합니다.
- 심볼, 타임프레임, lot, magic number, dry_run 설정을 추가합니다.

완료 기준:

- 전략 설정을 API와 런타임에서 같은 구조로 읽을 수 있습니다.
- 기본값은 제품 명세의 기본 파라미터와 일치합니다.

## 2단계: 지표 계산 엔진

- SMA, 표준편차, ATR, highest, lowest 계산 유틸을 구현합니다.
- BB-ICHI 클라우드 산출값을 구현합니다.
- Kizun 매매선을 구현합니다.
- Supertrend trend, up, dn 전이를 구현합니다.

완료 기준:

- Pine Script와 동일한 입력 캔들에 대해 주요 산출값이 허용 오차 안에서 일치합니다.
- lookback이 부족할 때는 신호를 생성하지 않습니다.

## 3단계: 전략 상태 머신

- `freshLong`, `freshShort`, `goLong`, `goShort`를 구현합니다.
- `posState`, `posEntry`, `posSL`, `posTP1`, `tp1Hit`, `trailActive`를 서버 상태로 관리합니다.
- TP1 전 SL, TP1 본절 이동, 트레일링 SL, 트레일 청산을 순서대로 처리합니다.
- 반대 신호 청산 후 신규 진입 정책을 구현합니다.

완료 기준:

- 같은 캔들 시퀀스를 여러 번 실행해도 같은 신호와 상태 전이가 나옵니다.
- 모든 상태 전이가 구조화된 로그로 남습니다.

## 4단계: MT5 주문 연결

- 전략 주문과 수동 주문을 구분할 magic number와 comment 규칙을 정합니다.
- 시장가 진입, 포지션 청산, SL 수정 기능을 MT5Bridge에 추가합니다.
- dry_run 모드에서는 주문 의도만 기록하고 실제 주문은 보내지 않습니다.
- 실거래 모드에서는 계좌 연결, 심볼 활성화, 스프레드, 최소 lot, 최대 lot을 확인합니다.

완료 기준:

- 데모 계좌에서 주문 생성, 청산, SL 수정이 재현됩니다.
- 주문 실패 시 전략 상태가 실제 MT5 포지션과 어긋나지 않습니다.

## 5단계: 런타임

- 봉 마감 기준으로 전략을 실행합니다.
- 심볼과 타임프레임별 마지막 처리 봉을 저장합니다.
- 서버 재시작 시 MT5 포지션과 전략 상태를 복구합니다.
- 웹소켓으로 전략 상태, 최근 신호, 포지션 상태를 전달합니다.

완료 기준:

- 같은 봉을 중복 처리하지 않습니다.
- 서버 재시작 후 열린 포지션을 인식합니다.

## 6단계: UI

- 전략 페이지에 Red-Green 메인 전략 카드를 추가합니다.
- 시작, 중지, dry_run, 실거래 모드 상태를 표시합니다.
- 현재 파라미터, 마지막 신호, 포지션 상태, SL/TP1/Trail 상태를 표시합니다.
- 실거래 전 확인 절차를 둡니다.

완료 기준:

- 사용자가 전략이 왜 진입 또는 미진입 상태인지 확인할 수 있습니다.
- 실거래 활성화는 명시적 확인 없이 켜지지 않습니다.

## 7단계: 검증

- 지표 계산 단위 테스트를 추가합니다.
- 전략 상태 머신 테스트를 추가합니다.
- MT5Bridge는 mock provider로 주문 실패, 부분 실패, 재시도 케이스를 검증합니다.
- 데모 계좌 실행 로그를 보관합니다.

완료 기준:

- 최소한 지표 계산, 신호 생성, SL/TP 상태 전이, 주문 의도 생성 테스트가 통과합니다.
- 실거래 전 체크리스트가 문서와 UI에 반영됩니다.

## 열려 있는 결정

- 기본 심볼과 타임프레임
- 기본 lot 또는 계좌 리스크 비율
- TP1에서 실제 부분청산을 할지 여부
- 거래 시간 필터 적용 여부
- 최대 손실 제한: 일간 손실, 연속 손실, 최대 DD 기준
